Sandbox

Free play. Everything from the guided paths, running continuously. Turn on failures, break the design on purpose (for example, switch idempotency off), then press Reconcile to see the damage. New here? Start with the RabbitMQ path or the Kafka path.

Challenges
  1. RabbitMQ: make the ledger fail reconciliation using only the "Order" setting and crashes. Why did it happen?
  2. RabbitMQ: set failure rate to 60%, publish 20 events, and get back to "Reconciled" without changing the code.
  3. Kafka: produce a stale account status. Which checkbox did it take?
  4. Kafka: replay from offset 0 and keep the ledger correct. Then do it again with idempotency off.
  5. Kafka: set 4 consumers. What does the 4th one do, and why?

Kafka simulator

Topic ledger.events has 3 partitions; records are keyed by account, so each account always lands in the same partition. The consumer group splits partitions between consumers. Blue outline = next record to read; green edge = committed offset. Records stay in the log after they're read.
